### C. Page-object classes

Location: src/main/java/, following the newly defined page package conventions.

This is a mandatory design requirement.

Implement Page Object Model using Selenium 4 and PageFactory, following the requirements and examples in this prompt.

Use private WebElement fields annotated with @FindBy.

Example:

    public class ExamplePage {

        private final WebDriver driver;
        private final WebDriverWait wait;

        @FindBy(id = "exampleField")
        private WebElement exampleField;

        @FindBy(css = "button[type='submit']")
        private WebElement submitButton;

        public ExamplePage(WebDriver driver) {
            this.driver = driver;
            this.wait = new WebDriverWait(
                driver, Duration.ofSeconds(10));
            PageFactory.initElements(driver, this);
        }

        public WebElement getExampleField() {
            return exampleField;
        }

        public WebElement getSubmitButton() {
            return submitButton;
        }

        public void enterExampleValue(String value) {
            wait.until(
                ExpectedConditions.visibilityOf(exampleField));
            exampleField.clear();
            exampleField.sendKeys(value);
        }

        public void clickSubmit() {
            wait.until(
                ExpectedConditions.elementToBeClickable(submitButton));
            submitButton.click();
        }
    }

Adapt the code to the project's actual conventions and Java version. Add the necessary Selenium imports.

Page-object rules:

1. Declare WebElement fields as private.
2. Use @FindBy for stable, known page elements.
3. Initialize PageFactory in the page constructor.
4. Use getters for WebElement access where that is the established project convention.
5. Keep locators centralized in their page objects.
6. Never scatter hardcoded XPath or CSS selectors across step definitions.
7. Use meaningful method names that describe user actions or business operations.
8. Keep page-specific business operations inside page objects.
9. Do not expose unnecessary implementation details to test classes.
10. Reuse generated page objects rather than creating duplicate classes for the same page.
11. Do not create public setters for WebElement fields merely to satisfy a getter/setter requirement. Use setters for configuration, test data, or model objects when appropriate.
12. Use constructor injection for WebDriver when that matches the defined architecture.
13. Do not use static WebDriver fields in page objects.
14. Do not create multiple PageFactory instances for the same page unnecessarily.
15. Add only locators supported by the inspected application or verified test requirements.

If an element locator is unknown, inspect existing code, available application markup, or supplied evidence. Do not invent a supposedly verified locator. Clearly identify unresolved locators.

Use Selenium 4's Duration-based WebDriverWait API.

Prefer explicit waits for visibility, clickability, presence, and expected state. Avoid fixed Thread.sleep calls except for a documented case where no appropriate condition is available.

Do not mix implicit and explicit waits indiscriminately.

For complex interactions, use small page-object helper methods rather than duplicating synchronization logic.
